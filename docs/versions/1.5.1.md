Version 1.5.1: a fix to 1.5.0.

## Fix

`ameesh projects`, as well as the projects view at the top of `ameesh progress`, failed with `invalid input syntax for type bigint: "dh-6b-ii-c"` as soon as an agent had a session lot whose identifier is not numeric.

The query filtered these identifiers with a regular expression, then converted them to a number in the same `WHERE`. But Postgres does not guarantee the evaluation order of the conditions of a `WHERE`, and the conversion could run before the filter. It now happens in a `CASE`.

Checked against the production database in read-only mode (`default_transaction_read_only=on`): the command returns the full view again.

## Deployment

No migration. Install the version, then restart the runners when convenient: the fix only touches read commands.
