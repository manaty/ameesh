Version 1.6.0: six lots, five migrations (0043 to 0047).

## Lots

* **L73**: ameesh cleans up what its agents create — a temporary directory per agent and per session, worktrees removed at the end of a lot, labelled containers, `ameesh menage`, alerts `tmpfs_full`, `worktree_kept`, `tmp_orphan` (migration 0045).
* **L94**: under-use alerts as much as overload — `plan_underused`, `idle_capacity`, `orchestrator_held`, `host_underused`, and `balance_low` for pay-per-token providers.
* **L95**: an accurate progress page and budget — pay-per-token spending and plan value never added together, real spending taken from balances, `ameesh cost correct` (migration 0043).
* **L96**: roadmap — planned dates, dated commitments, Gantt, `ameesh plan`, `ameesh work plan`, alert `engagement_overdue` (migration 0044).
* **L105**: caps also act during a turn — maximum duration and bounded mail per turn (migration 0046).
* **L106**: surviving a host outage — harness binaries resolved without the session PATH, "host not ready" instead of fast failures, battery and mains power, resumption of a dead `attach` session (migration 0047, developed under number 0106).

## Integration

* Each lot is merged with `--no-ff`. L95 and L96 start from integ/l60-l74, whose content is that of 1.5.0; their three-way merge is taken from that base.
* Conflicts resolved by union: alert types (`exploitation.ALERT_TYPES`, `notify.DEFAULT_TYPES`, `TYPE_LABELS`, deduplication key), thresholds and reading columns (`resources.THRESHOLD_KEYS`, `hosts.READING_COLUMNS`), progress page (L95 and L96), `runner.py`, `adapters.py` (L105 and L106), `tests/fakebin/claude`, `deploy/sql/role-superviseur.sql`, `docs/design/log.md`.
* `integ:` migration 0106 renumbered 0047; an organisation name removed from a docstring; `vm.sh redemarrer` requires 0041 to 0047.

## Deployment

Procedure: `docs/BASCULE.md`, "Mise à jour vers 1.6.0". Migrate **before** restarting: a 1.6.0 runner writes the columns of 0045 and 0047 at each reading. The migrations are additive; the old code runs on a migrated database. Then: supervisor role reapplied, the ghost agent `orchestrator` stopped, PATH drop-in for the runner of the old database, runners restarted one by one outside a turn, `ameesh doctor --harness`.
