**Review and merge**
- Packet guard (#2333, canon §11 bis, owner decision of 18/10 "everything goes through a batch", home#107): a work head (`lot/**`, `agent/**`, `review/**`, and by default anything that is not `integration/**` or an integration ref) is no longer merged directly into an integration target (`main`, `develop`, `release/**`), and no `ci-lot-<sha>` label is set between two batches. `work merge-pr`, `work fire --sha`, the auto-merge pass (which disarms a residual auto-merge), `ci run`, the landing queue (`land._fire_guard`, last gesture of the `local` and `pr` routes) and the queue admission (`work queue add` refuses early with the §11 bis message) all go through `packet_guard`. An `integration/**` head passes; a motivated `incident|unblock` exception is journaled on the lot (`packet-exception <kind> sha=<40hex> reason=…`) and covers only the head it names; `merge-pr --dry-run --exception` validates it without writing it (#1003 N1).
- Out-of-API merge and fire require the target's required checks (#2273, #2285, #2286): `ameesh work merge-pr` read CI only through `radar.ci_green` (which counts SKIPPED as green) and never checked that the target's required checks were present, so the rollup of PR #1638 passed (coverage green, batch suite skipped, no `tests`). The path now applies the fire's reading (`fire.required_checks`, `fire._required_gap`) with the provenance of the exact head (`commits/<sha>/check-runs`) when the protection imposes an application; names are compared exactly. The fire also reads the required checks of branch rulesets (`rules/branches/<target>`, `integration_id` imposing the application), treats `app_id: -1` as "any application" and replays `gh api --paginate` without `--slurp` (unknown flag on the host's gh 2.45, which made every head with an imposed application refuse); a declaration never removes a reading that succeeded (#2285). The queue route (`land=local`, Nexlink) proves each declared context on the frozen head, check runs and commit statuses, fail-closed, at the last gesture, with or without fire milestone (#2286). A malformed or non-GitHub slug is refused instead of being taken for a local transport (#2289).
- A transient forge read no longer ejects a line from the queue (#2306): 5xx, 408, 429, timeout, DNS or network cut, empty output and a simple EOF raise `TransientLandError` and the line stays queued (`retry`, lease released); a 4xx, a proven gap or a malformed answer remain proven refusals. An empty target no longer skips the required-checks guard and the status pagination follows the announced `total_count`. The retries are bounded (#2345): the journal's `RETRY_NOTE` notes since admission are counted and the line is ejected closed beyond `AMEESH_LAND_TRANSIENT_RETRIES` (default 6), with nothing merged and the assignee woken with the way out.
- Admission applies the class and the two families of the frozen diff (#2338): a critical head (SQL, security, prod) could enter with a single family and be withdrawn after the freeze; the policy provider now classifies the exact diff and carries the merge gate's minimum (two families for critical domains). The class is read on `origin/<target>` before the local target (a worktree behind `origin/main` had classified light lots as sensitive), fetched with the branch and compared against the same fresh target commit, and the release axis follows the resolved target when the line has none (#2207, with #2284's comment aligned on the fallback).
- Critical policy drift (#2265, #2263): a critical review is kept despite a canon drift, `critical_scope` no longer skips light paths, and the class is preserved per file between canons (the maximum is kept, whatever the order of the canons); lightly-classified Markdown documentation escapes the fallback patterns (41 documentation files would otherwise have asked for two reviews) and only becomes critical through `critical: true`. `merge_pr`, `lot_class` and `review` count for the merge gate: a diff touching them asks for two reviews of distinct families (#2249, covered by #2265).
- `--avis 0 --full` is reserved to the carrier (#2240): the declared review count is written in the CI label mark (`avis=N`, zero included; an older mark stays readable), and zero reviews require the carrier's own manifest `reviews/integration-<name>.md` at the frozen head and absent from the PR base (a directory is not a manifest; an unreadable read refuses). The guard only touches the CI request, not the required checks, `review_gate` or the carrier's merge gate.
- Fire and radar passes re-read the host's `radar` configuration on every pass (#2212): a runner started before a project declared `land` kept its startup configuration and merged that project directly on GitHub (Nexlink package 48, 17/10). An unreadable or vanished file fails the pass, which is logged and retried, never falling back to conditions without a queue. Pilot waiver `--no-verdict` honoured (dispensation posted on 18/10).
- Follow-ups of #2076 (#2204, #2346, migration 0462): the withdrawal of a reviewer who became assignee is journaled even through direct SQL (an AFTER trigger names the withdrawn name; Python paths set `ameesh.reviewer_audit`), re-designating a present name puts it last, a blocking verdict of an undesignated or withdrawn reviewer no longer holds the lot in fix, `seb` and `human:seb` name the same actor, and `roadmap` exposes `reviewer`/`reviewers` like progress and list. A current blocking verdict still holds the lot without designation or with `-none` (the waiver guard of #1979 is not bypassed). The alias applies only if the bare name is not a registered agent, and the audit flag covers only the Python path's UPDATE, so a direct SQL withdrawal in the same transaction is still journaled.

**Fleet health**
