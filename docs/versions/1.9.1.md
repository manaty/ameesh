Patch version, released by PR #416, from lot #347 / PR #333 (`e2a2c1944`) on base `release/1.9`, narrowed to automatic mail inheritance and identity fixes. It brings no new command, option, setting, migration or alert type.

**Mail and lots**
- L118c: `agent-mail send --new-lot` no longer creates a lot with an empty project when the sender's or the recipient's project is known. The sender's project is inherited first, then the recipient's — registry data first, then an unambiguous project from the agent's own canon as fallback. Unknown projects keep 1.9.0's unclassified creation behaviour; conflicting own-canon projects refuse the inheritance (lot #347, PR #333).
- Repairing the lots already created with an empty project is outside this patch.

**Identity and corrections**
- The correction guard now rejects invalid runner/session identities before any human fallback, and requires the correction roles to come from the agent's own canon. Regression tests exercise both attacks through the existing `work move --correct` command (lot #347).

**Validation**
- 140 tests passed under `ameesh heavy` (2 skipped), covering `test_l118c_mail_projects`, `test_l118_assignments`, `test_l124_decisions`, `test_l26_exploitation`, `test_l37_mode_et_alertes` and `test_l157_estimations`; `git diff --check` passes and the L158 checker accepts the range `1.9.0 → 1.9.1` as a patch.
