**Review and merge**
- The fire now requires the target's required checks on the frozen head (#2271, closes #1647). `fire.ready_pr` used to read only `status.ci`, which counted `SKIPPED` as green and ignored branch protection: PR #1638 was merged with coverage green, the batch suite skipped and no `tests` check. The fire reads the target's protection at the forge and requires each required check in `success` on the frozen head, from the imposed application (`tests`, app 15368 on `main`), with exact context names; an absent, skipped, pending, foreign-app or other-head check leaves the PR not ready, on both merge paths. An abbreviated freeze (7+ characters) names the same head.
- The pilot's no-verdict waiver (`work reviewer --no-verdict`, #1979) is honoured by the shared queue and fire gate, re-read after the milestones so that a freeze of another head committed in between never lets the new head in without reviews; a blocking verdict is never lifted and a draft PR stays refused. The queue note names the author of the waiver, read from the lot journal (#2281).
- `critical_scope` reads only the changed paths of the classified diff, no longer the files cited by the classifying rule; an empty file list counts as critical, and `approve_check.py`, `approve_client.py` and `config.py` join the security scope (#2218). An end-to-end witness proves that the gate derives its required reviews from the canon's classification, not from a forced class (#2264); the `blocked` witnesses of `test_1003_merge_pr` now assert the blocking message itself (#1630).
- Multiple designated reviewers (#2076, migration 0456): designations accumulate in `work_items.reviewers` instead of replacing each other, the gate waits for each reviewer's verdict on the current head, and a delayed review of another commit keeps a current blocker. `--remove` withdraws a name explicitly; the trigger keeps older runners that write only `reviewer` compatible. Removals caused by an assignment or delegation get their own journal line, and a `--remove` without effect no longer logs a false "removed" (#2084). A designation of a reviewer with the same declared harness as the author prints an advisory warning on stderr (#800).
- A designated reviewer who still owes a verdict on the frozen head counts as busy: automatic pickup no longer hands them another lot and the underuse alert no longer lists them (#1726).
- A merge recorded outside the queue opens the post-merge review lot (#1104, migration 0438). Catch-up is bounded by the activation time written by 0438, so the roughly 1 019 earlier merges never become due reviews; the `already` path of `close_merged` respects the same bound.
- `ameesh work merged` recognizes a real GitHub merge commit of the branch recorded on the lot (`Merge pull request #N from <owner>/<branch>`, the owner being the lot's canonical repository; a fork homonym proves nothing) and prints the finding (lot, title, subject, proof form) before writing (#1400).
- The branch sweep no longer closes a lot cited as negated in a merge title (#2259): Nexlink commit 84c68e9d4 ("recomposition sans #598 ni correctif .github") had closed #598, whose PR was still open, and wrongly freed #2227. Prepositions (`sans`, `ni`, `hors`, `sauf`, `without`, `except`) negate what follows them, participles (`retiré`, `exclu`, `revert`…) negate the whole clause, parentheses are handled, and `ameesh-work:` trailers and `lot/<id>-…` branch merges are unchanged.
- The conflict radar no longer re-sends the same notice while a conflict's inputs are unchanged (#1186×#800 about ten times in one hour): pair, stale and target conflicts carry a fingerprint (lot heads, target head, resolution commit) and a key that leaves a pass stays dormant while its lots stay on the radar (#2238).
- Commit provenance (#1465, migration 0445): each commit made in a turn gets an append-only receipt (actor, session, turn, harness) through a `pre-commit`/`post-commit` hook pair (`ameesh provenance install|intent|created|record`), and a freeze or verdict milestone writes its proof in the same transaction; a missing proof is `unknown`, never guessed from a nearby turn. The runner installs the hooks once per opened session, never in mediated mode, and never overwrites a foreign hook. Review follow-ups: no proof for a non-hexadecimal declared sha, `--end-of-options` on revisions, hooks placed under `core.hooksPath`, foreign hooks recognised by their exact signature line (#1534).
- `scripts/rebase-lot.sh`: a lost `#<id>` subject is detected only among the commits produced by the rebase, including multi-line bodies (#2043); the #1669 checks (lot prefix, conflict markers) still run on a state file written by another version of the script (#2186).

**Alerts and SLO**
- SLO handover grace (#2217): a lot that was just reassigned or taken gets 30 min (`HANDOVER_GRACE_S`) during which an overdue step is still measured but not escalated, so no immediate "reassign again" alert (#2180 alerted 3 min after its reassignment, #660 3 min after its pickup). Automatic pickups now date the assignment; a return to the queue opens no grace.
- An SLO alert on a merge wait or a blocked lot targets the pilot (bureau and auditor kept at level 3), no longer the holder, and the GO→merge clock starts only once the required reviews are acquired on the frozen head (#2231).
- Alert orchestrators are those declared (`--orchestrators`, `AMEESH_ALERT_ORCHESTRATORS`) or holding the orchestrator role in the canon; 30 days of assigned lots no longer make an agent an alert recipient (#1114).
- Long budget pause: a new `budget_pause_long` alert names any agent paused on budget beyond 3 600 s (`--long-budget-pause`, `AMEESH_ALERT_LONG_BUDGET_PAUSE`, 0 disables), mailed to orchestrators and auditors with the commands to run (#1466).
- A pilot's `hold: <reason>` note extinguishes the stale alert and its 6 h re-nudge like a declared dependency, until `unhold:`/`hold lifted:` or a state change; the pilot identity is authenticated on the write path (a `--actor human:…` spoof is refused) and holds appear on the progress page (#1664).
- `notify.run_pass` without explicit thresholds now observes the perimeter it declares (#2105).

**Agents and accounts**
- The runner reloads its configuration without restart (#1466): accounts, ceilings, critical roles, non-critical share, fallback harness, harness binaries and provenance follow a changed file at the next turn boundary, before the budget guards; storage, lease and cadences keep their startup values, and a broken or vanished file keeps the last valid configuration. A profile under `~/.config/ameesh/runner-profiles/` now inherits from `config.json` (its own keys win, overridden keys are shown); `ameesh doctor` and `ameesh accounts list` say where the configuration comes from.
- A finished lot's turn no longer runs in the session of another open lot: that session is parked and the turn runs in a session without lot; a refused switch defers the turn (#2055). The lot brief says "put aside" only when a session was actually parked (#2242).
- Operator pause is visible: `show`, `projects`, progress and alerts read it, `plan_underused` no longer proposes a paused agent, and waking or assigning a paused agent is refused with its way out (#2200).
- `plan_underused` no longer promises short-window capacity of an account whose general window has reached its fixed or overage ceiling (#2233). Account freshness docstrings match #1566, with a witness for a future, infinite or NaN `read_at` (#1896).
- An orchestrator can take a lot when no other taker exists (traced in the note), without notifying itself (#1739).
- The resident Claude `argv()` is idempotent: a second call before any turn repeats the same creation (`--session-id`), never `--resume` on the new id (#2008).
- `paused_on_budget` is also in `show --json` and `GET /api/v1/agents/{a}`; #1070 code moved to English (#1186).
- Lot-directory notes (L243-4) read only the pass's candidate ids instead of the journal of every closed lot (#2162).
- During a database outage, the last lease renewal aims at half the remaining margin instead of the deadline, which `renew()` refused (#2172).
