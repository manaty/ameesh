**Fleet health**
- Host housekeeping is shared across runners (#2167, incident vehicle). One pass runs at a time per host, under an OS lock shared by every runner process and the CLI: a second pass is skipped ("another housekeeping pass is running on this host") instead of scanning the same disk again. Periodic passes share the timestamp of the last completed pass per mesh, so a host is swept at most once per interval whatever its number of runners; an explicit or pressure-triggered pass bypasses the interval, and a dry run never postpones real cleanup. The first periodic pass of each runner is staggered by a random delay of up to one period. On worktrees and attributed orphans, the process-holder check now comes before Git, so a path held by a process no longer pays a `git status` first.
- Worktree housekeeping reads every tracked worktree instead of the 500 oldest (822 tracked on agents-1, 789 on agents-2, 1 309 on the workstation; 0 removable on the 17/10 dry run). The copy of a lot assigned to another agent is no longer kept forever: if that lot is finished, the orphan rule applies (24 h without source or Git activity, clean, pushed, no process, branch kept); an open, unknown or unreadable lot is kept as before (#2174).
- Process and zombie counts (#2022, migration 0455; it was withdrawn from 1.11.4). Every runner counts the host's processes and zombies and those among its own descendants. `host_zombies` is raised at `max_zombies` (default 200, critical at 10x) and names the runners leaving them; it is a warning, no pause. An early disk warning `host_disk_soon_full` fires above 85 % used, under 15 GiB free, or when the 6 h trend reaches the floor within a day; host alerts are sorted and pushed first. `ameesh hosts --fleet` prints one line per publishing host (age, STALE beyond 1 h, worst disk, zombies, breaches), `--publish` writes a reading for a host without a runner, and `--send NAME` mails the fleet summary. The systemd templates `ameesh-host-publish.{service,timer}` and `ameesh-fleet-summary.{service,timer}` are shipped but not installed. A count longer than Python's integer digit limit no longer crashes the host policy (#2120).
- Runner memory (#2096): two identical large turns used to add 77 MB of RSS; they now add about 2.4 MB. The kept final text is bounded to its first 64 000 characters (what the readers use), the summary fallback is bounded in characters, the raw stream line is logged without a copy, and the runner returns free arenas to the kernel (`malloc_trim`) after a turn that grew RSS by more than 32 MiB. `CostBook.events` reads only the requested slice of `events.jsonl` instead of the whole file: on a real 75 MB journal, 1.40 s and a 621 MB peak became 0.004 s for `session_of` and 0.043 s for the last 200 events. Lines are split on `\n` only, so an event holding U+2028 is no longer lost (#2110). The memory log line says why nothing was released ("nothing to release" versus a platform without `malloc_trim`) (#2107, #2108).
- Runner liveness (#508, migration 0411): each runner writes `runner_seen_at/host/owner` for the `execute` personas of its host, independent of the lease, the gate and capacity, at most once per 60 s (`AMEESH_RUNNER_LIVENESS_INTERVAL` can raise it). `ameesh show --json` and `ameesh list --json` expose it, so a restart can be checked without a lease. The supervisor role reads the three columns on the table and on the `agent_mesh_overview` view.
- A turn deferred because a third party holds the `session-use` lock is no longer retried every 0.5 s forever: after two handoff timeouts the worker logs once, sets the "session lock held" status (fenced by the lease, never over another block) and spaces retries up to 30 s. A requested attach keeps the short step (#1914).
- Lease renewal: the wait now keeps a full slice (ttl/3) before the deadline, and retries after a failed renewal use the short delay, bounded by the lease. Under load, workers had been giving up still-valid leases ("renewal unanswered past the lease") (#2139).
- When the per-turn cgroup placement is refused, the trampoline removes the empty turn cgroup itself instead of leaving it to a later sweep (#1641).
- Host availability registry: a truncated or unknown-schema registry is no longer rewritten with only the writing host (the other hosts' lines were lost); it raises a dedicated `host_gate_unreadable` alert (#2128, #2127). A malformed host row no longer brings down the alert pass: it is skipped and named, and the family is marked unread (#2129). An unread family no longer resolves an acknowledgement, and notify no longer announces a resolution it never observed (#1901).

**Agents and accounts**
- Automatic pickup (#1677): a lot stacked on a blocker in `qa` whose latest verdict is ok can now be taken, and the pickup mail names the blocker, its branch and its frozen head. Idleness is read from the agent's actionable lots, not from the time since its last turn. When nothing can be taken, idle agents are offered reviews first (a `qa` lot without verdict, to an agent of the other model family than the author's), then corrections (latest verdict blocking, author busy), at most 6 per hour and not re-offered within 6 h; the author is excluded.
- The anti-improvement gate counts only startable lots: a lot held by a planned wait (explicit dependency, `depends_on`, start date to come) no longer stops idle agents from taking improvement work, and `backlog_empty` speaks when only planned lots wait (#1625).
- Multi-project lots run in their project directory (#811): the registry cwd stays the primary one, each lot resumes only in the directory where its session opened, and a declared secondary project is picked up once its directory exists. A missing secondary directory defers only that lot, with its mail and instructions held, while the agent's primary turns continue; 200 held messages no longer hide a deliverable one. A refused switch no longer runs the turn in the previous lot's session. One refusal note per item instead of one per agent, with the item's journal read once per pass (#1538). A pre-0384 session without origin, on the agent's own lot and in its own directory, is adopted under a fenced write instead of being force-switched (#1900). docs/ORCHESTRATEUR.md L165 describes pickup by the lot's project (#1882).
- Stopping an agent (`ameesh stop`, and each runner sweep) returns its open lots to the team queue, with a journal note and the delegation cancelled; promoted lots whose measurement is still due go to the auditor, never to a stopped one, and `orphan_lot` now also reports promoted lots (#753, brought by #1425). #1425 runs this release after the sweep's guards and resolves the measurement actor only when needed.
- Gauge readings (#1132, migration 0434): readings carry their production time and source journal, and readers order by production time first. A stale reading re-inserted later can no longer replace a fresher one (13/10 incident: seven_day 67 % overwrote 87 % and admission went under the 80 % overage ceiling). Between two dated readings the most recent wins, widget or journal; the widget keeps priority on a tie or without a date (#1648). A Claude stream without account marker is no longer dated by the journal's file time (#1720). A partial reading that is still informative keeps a current rank, and an undated open window no longer counts as reset (#1566). An unreadable gauge leaves its account line in `ameesh accounts list` with the reason instead of failing the command (#1600).
- DeepSeek: only the seven transient `dsh: <CODE>:` codes (RATE_LIMIT, SERVER, MALFORMED_RESPONSE, STREAM_CLOSED, EMPTY_RESPONSE, TIMEOUT, TRANSPORT) are retried as transient; `dsh: QUOTA:` is a quota and other codes stay unclassified (#1592). The wake on the retry deadline has a direct witness (#1593).
- `ameesh accounts login` (L232d, #366), source only, nothing activated: pinned claude/codex/gh adapters (`--console`, `setup-token`, `--clipboard` and `--insecure-storage` refused), the authorization URL and one-time code shown only in a private view of ameesh-approve after a WebAuthn assertion, a signed receipt without secrets, one live challenge per (host, provider, account), and `done` requires a clean provider exit before the health probe. The login API is closed by default and requires a dedicated token distinct from the team token.
- The status line cache key includes the agent name, so two sessions without session id in one directory no longer share a line; the hook's completion marker no longer reacts to an outer exception (#1628).

**Alerts**
- Acknowledgement perimeter (L87c, #1473, migration 0457): an acknowledgement records the thresholds under which it was taken, and only a pass that observes the same perimeter can declare it resolved. A narrower reading no longer turns an acknowledgement into "resolved" without an observed resolution.
- A `stale_lot` brief without assignee goes to the orchestrators of the lot's team (its own, its package's or parent's, else its app), no longer to every orchestrator: an ameesh lot no longer wakes the Nexlink orchestrators (#917).
- SLO: a phase passed without a build timestamp is not measurable, so no more invented "late by 0 min"; the level-2 brief goes to the declared pilot, not to historical assigners (#1982).
- Process rules: after a forced rewrite of the canon history, the divergence is reported (`canon sync`: "rules (Process) NOT pushed", and one runner line per incident and per canon) instead of rule mails stopping silently; the default-canon copy keeps `process_commit` (#1464).

**Review and merge**
- Pilot fire at freeze (#1374, migration 0437): `ameesh work fire <lot> --sha <commit>` authorizes the merge of that exact frozen head, and `--withdraw` revokes it. At each branch sweep, a lot with a fire passes the verdict gate first (required independent verdicts on the frozen head), then gets its PR or queue entry, and in GitHub mode is merged by the sweep itself with `gh pr merge --match-head-commit`; no GitHub auto-merge is left armed between passes. A moved head invalidates the fire. Land lock keys are canonical (`origin/main`, `refs/heads/main` → `main`). The `_target_lock` docstring and the deployment window of the canonical key are documented (#1508, #1509).
- `work merged --sha` refuses a declaration unrelated to the lot: the commit must be in the lot's repository, an ancestor of the target and carry the lot marker; canonical commit ids are stored (#1286). Its "unknown actor" witness now intercepts the function really called (#2094).
- `ameesh work branch <id> [<branch>] --detach --reason R` detaches an obsolete branch without changing state, holder or reviewer; the sweep no longer re-associates a detached `lot/<id>-…` branch, and a no-ff merge citing it no longer closes the lot (#2102, closes #1505). The detach is conditional (refused if the branch changed meanwhile), and the merged PR of a detached branch no longer designates the lot (#2131).
- Review lots: freezes are read newest first and the first one whose actor held the lot is kept; a third-party re-freeze is named in the review lot (#1859).
- Resolutions and radar: rerere training learns both merge directions, with a versioned cache so existing radars retrain (#2136); the Python port records the preimage of the real merge (#2165); replay and training read `.gitattributes` from the target tree, in a separate cache retrained when the target's attributes change (#2189); a conflict that survives removing a lot's delta is inherited and no longer attributed to that lot (#2104); `work resolve --done` is idempotent and cleans up from the main worktree (no more "git not found") (#2142); the migration probe ignores numbers already landed by finished lots (11 false alerts 499..509 on the `release/*` cut, #2146).
- Batch composition: `scripts/paquet-compose.py` composes a unit with `git merge --no-ff` and writes one `ameesh-work: <lot>` trailer per lot, so the composition commit can be declared with `work merged --sha` and is seen by `sync-branches` even when the transported head differs from the recorded freeze. On conflict nothing is committed and the message waits in `.git/MERGE_MSG` (#2157).
- `scripts/rebase-lot.sh`: every replayed commit of a `lot/<id>` branch must start with `#<id>` and introduce no conflict marker (exit 4) (#1669); valid git options (`-k`, `--keep-empty`…) are accepted and voluntary drops are listed, not reported as losses (#1516).
- docs/EXPLOITATION.md states the content proof of the "already landed" shortcut (#2045).

**CI**
- The batch gate `paquet.yml` grants `actions: read` to the reusable `tests.yml`; without it GitHub refused the file (`startup_failure`, no job) precisely when the full suite had to run (#2134). The hosted-runner relaunch guard also covers batch runs (#2119).
- CI watcher (#1161): runs in `pending`, `requested` or `waiting` are tracked. Unstarted runs of a superseded head that hold the current head's concurrency group are cancelled through the API (same PR, source repository and workflow; never `main`, `release/…` or the current head), and a PR run pending for more than 5 min is reported to the assignee.
- GitHub read cache: keys carry the client (API base, truncated token fingerprint, gh host and config dir), the resource is known before the request, and a "secondary rate limit" 403/429 blocks that resource (#1405).
- Map (`carte`) workflow: automatic runs are suspended (manual `workflow_dispatch` only) after the artifact quota incident (#2116); the assembly job's ceiling is 30 min (#2175); the fake ACP agent saves its coverage before SIGTERM, so no empty coverage file makes the map partial (#2177); map corruption fixtures use a small source tree (34 tests in 19 s instead of 1437 s, #2151 for #1770). The attribution contract refuses a test class bound into another module, including by assignment or `import *` (#1632, #1944).
- Test plan: a `sys`/`os` module named through a walrus now cuts the import proof (#1906).
- Test hygiene: the signal/journal order witnesses no longer depend on the journal thread (#971); the attach test confines its saturated log sink, which leaked into `test_l109_mediated_mode` (#2199).

**Deployment**
- `vm.sh redemarrer` drains an agent that chains turns (#2152, migration 0458): after `DRAIN_ATTENTE` (300 s, 0 = never) it sets a named operator pause, waits for the turn to end (no turn interrupted), restarts the unit and lifts the pause. Lifting is conditional (`ameesh resume --operator --expect-reason`, compared and lifted in one SQL statement), so another actor's pause is never lifted; a lost reply is reconciled from `show --json`, and an exit trap lifts the drain on every path.
- Atomic venv switch (#1969): `deploy/mise-a-jour/bascule.py` prepares a versioned venv aside (pip, import, `--version` and shebang checks) and switches with a single rename; the live venv only holds launchers, rollback re-points to the kept version without pip, and `poste.sh` and `vm.sh` use it. The root helper no longer goes through the shared `/tmp`.
- Staging mail health probe (#2190): a probe only targets a persona with a live lease that is idle and not operator-paused; a named target in a turn or paused is refused as "no probe" instead of being measured in the queue, and the target is re-read just before sending. Without a free persona the verdict is a named "no probe", not a KO. Every verdict is written as a JSON report, and a KO report is kept in the trace and the notification.
- L232b, source only: an operator entry assembles the reviewed bundle and enrolls the probe turn (`turn.json`) for an agent registered on that exact host, with one validator shared with the controller (#910); the release role audit also fails on sequence privileges (#2023); an inventory without `source_bytes` is refused and must be re-dumped (#974). Nothing is installed or executed on a host.
