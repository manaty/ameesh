Patch release of the 23:00 cut of 16/10/2026 (build/beta rhythm, canon §11 bis, hourly batches home#94). It brings 76 lots merged in four scripted batches: #1429 (10:30, 11 lots), #1470 (12:00, 14 lots), #1484 (14:45, 33 lots) and #1500 (17:00, 18 lots, recomposed after its first CI: 11 lots withdrawn and postponed to the next batch). Two lot branches also bring earlier lots: #1573 brings #901 and #1789 brings #1580. Six additive migrations: 0417, 0425, 0429, 0439, 0444, 0454.

**Process workflows (TPK consumer contract, manaty/ameesh#1379)**
- Two transitions from the same stage under the same guard toward different targets now compile (#1915). 1.11.3 refused TPK's reference card (`draft -> backlog` and `draft -> sprint`, both under `planning`) with `edge-ambiguous`. The exact duplicate `(from, to, guard)` is still refused (`edge-duplicate`), and the registry still requires the explicit `(to_stage, guard)` of the command. Reviewed by Claude, no blocking finding.
- B/C seam (#1994): `read_sources` now projects the actor of each milestone, and the delivery id as a string. C attributes a verdict by its actor, so until now every real verdict was ignored (`completion-review-missing`, `verdict-missing`).
- A malformed `superseded_by` (`--3`, `²`) gets a named `evidence-invalid` refusal instead of an uncaught `ValueError` (#1995).
- Follow-ups of the Claude review of slice B (#1922):
  - an advance to a released core (merged, promoted, closed) carries the effects of a legacy close: migration reservation released, dependants woken once, close reason and milestones. Adopting or transferring a held lot requires the journal to prove the core before the hold. The lock order with the mailbox is fixed, and the registry, its tests and its design doc are in English (#1926);
  - closing a prerequisite no longer wakes a dependant pinned to a Process revision, and a legacy move or close refused by the pin names the Process hold (#1936).
- Everything stays opt-in per project.

**Fleet health**
- Test-bench Docker volumes were never removed (agents-1 at 99 % on 16/10). Housekeeping now removes a volume only when it carries `ameesh.bench=disposable` and no container has used it for `docker_volume_idle` (24 h), measured over successive passes. `scripts/pg-up.sh` sets that label only on a bench declared disposable (`AMEESH_PG_DISPOSABLE=1`), never on the shared bench volume. Other volumes are listed with the exact `docker volume rm` command, never removed (#2003).
- Ubuntu's `docker.io` has no buildx plugin: the build cache is now reported as unmeasurable instead of raising a permanent `docker_storage_unavailable` alert on agents-1/2 (#2012).
- A SIGTERM received while the runner waits for its database at startup is no longer swallowed: the runner exits 0 without a turn or lease. On 16/10 deepseek1 (agents-2) kept taking turns after `systemctl restart`. A signal received during an image replacement is honoured too (#2009).
- VM supervisor: after a stale gate it stops the container as before, then relaunches the executor without an operator if a fresh gate returns within 600 s (#1916). The window is measured on the monotonic clock (#1971), and its entry, the gate's return and its expiry are logged (#1972).
- Per-turn delegated cgroup v2 (L76c, #498, migration 0439): where the runner unit delegates (`Delegate=yes`, `DelegateSubgroup=runner`), each turn runs in its own cgroup, emptied by `cgroup.kill` at the end of the turn. Elsewhere the PID/PGID fallback applies unchanged, which stays the case until the unit setting is applied.
- Transient provider failures (429, explicit 5xx, transient DeepSeek `dsh:` errors, a cut Codex stream) are retried after 1, 2, 5 then 10 min without counting as fast failures (L48); after a mail or event turn, the executor opens a resume turn in the same session. An exhausted quota keeps the same pace but still counts for L48 (#1270).
- `ameesh doctor --harness` no longer reports a false KO for hooks written with `$HOME` (now expanded without a shell) or for the `veille` sender. On 16/10 this false KO triggered an automatic rollback of the staging deployment on pc-smichea (#1968, #1981).
- Concurrent canon syncs on one host no longer each mail the changed Process rules to every agent (14 identical copies of about 135 KB on 13/10): one sync claims the change and sends it (#793, migration 0425).

**Agents and accounts**
- Accounts (#1580, brought by its review follow-up #1789): the automatic choice ranks accounts by budget first (lag behind the pace, expiry of unused capacity, share lost at the next reset), and the declared order only breaks ties. Model-specific buckets, such as a weekly Fable bucket, are read from the usage widget for agents of that model. `ameesh accounts list` shows how many DeepSeek agents the plan margin could take (display only, no switch). `claude_gauges()` returns a `Gauges` on every path (#1661).
- Each agent's executor triggers lot pickup for the agents it serves, on their host, with the same safeguards, instead of relying on `ameesh notify` alone. A host under pressure is skipped with a local `host_pressure` alert (#804). The `balance_low` witness now proves the refusal of a free candidate (#935).
- Per-lot sessions: a finished lot no longer reopens a dedicated session at every turn, a stale `RESUME_PENDING` is removed, and a drift margin separates the host's file time from the database's `session_reset_at` (#1898). The clock comparison is documented (#1481).
- Operator pause (L87b): a host drain (L232a) is still served while the agent is paused, the stored reason is trimmed like the validated one, and a failed `resume --operator` names the right command (#1533, migration 0454).
- `attach --wait`: the handoff budget starts at the first session-lock conflict, and a deferred turn no longer counts as a fast failure (#1686).
- Resident Claude driver (L76): the liveness probe's asynchronous `system` events no longer land in the next turn's stream (#1816).
- Session adoption: a process holds a session only when the id is the argument of a resume selector (Codex grammar per binary), not any substring of its command line. A real DeepSeek process that quotes a test session id no longer blocks adoption (#1283). End-to-end witness of DeepSeek session resume (#806).
- With unreadable roles, the critical check used without an executor now treats the agent as critical (fail-closed), like the other two readers (L242c, #1904).
- `ameesh list`: the HARNESS column is 10 characters wide, so a starred 9-letter harness no longer shifts the row (#1782).

**Alerts**
- Persistent alert acknowledgement (L87c, #1463, migration 0444): `ameesh alerts ack KEY --human human:<name>` or `POST /api/v1/alerts/{key}/ack` silences one alert at its current severity, for its routed human recipient. The alert stays visible, and the acknowledgement ends when the alert resolves or changes severity.
- SLO briefs show the real delay and target instead of always "late by 0 min" (#1970).
- `estimate_bias` reminders go to declared pilots, the estimator and auditors, no longer to historical assigners (#1980).
- A brief relaunch goes to the recipients recorded when the alert was raised (#1787).

**Lots, reviews and hourly batches**
- Hot files of batch composition (#1517): `contract.json` no longer stores `interface_total` (it is derived from the table), and `tests/parts/*.txt` merge with git's union driver. 10 of the 28 conflicts of the 15/10 dry run were on `contract.json`. The radar's trial merges read merge attributes from the target's tree, also for pairs of lots (#1610), and the doc-readers job runs a module duplicated by the union only once (#1609).
- `work reviewer --remove` withdraws a wrong designation, and `--no-verdict` marks a head that needs no new verdict; a freeze of another head or a new designation lifts the mark (#1979).
- `work assign --if-holder AGENT` refuses a reassignment when the holder changed since the brief that proposed it, and `--force` does not bypass it (#2016). A `--claim` that falls back to the team queue fails ("claim refused", code 1), and the holder re-claiming its own lot is a no-op (#1787).
- `mail --lot` no longer records as the lot's branch a cited branch already carried by another lot. This could close a stacked lot when its parent merged (#1646).
- A light lot whose pilot routed the review after merge waits for the merge, not for a verdict: no more phantom "waiting: verdict" (#1822).
- `work show` labels `branch_head` as the head seen at the last sweep, with its date, instead of "last commit seen ahead", which misled two triages on 16/10 (#1899).
- Review lots (#1053): the model family is read from the freezing turn, and a freeze re-posted by a third party does not make it the author (#1777).
- Merge detection:
  - the local "already landed" shortcut judges the freeze's content: a lot whose composition was reverted is ejected instead of recorded as delivered, and empty freezes are covered (#1776);
  - in a partial clone, `plan_git.probe` makes one bounded fetch of a missing freeze before concluding that it is absent (#1772).
- Package sync: one lock per schema for all canons, `rebase_default` under that lock, and the lock wait no longer counts in `statement_timeout` (#831).
- Undeliverable mail sweep: exit code 1 only when a refused recipient was neither re-sent nor expired, and successors are tried most recent binding first (#1615).
- `work merged`: comment and witness details of the L122 delta (#1605).

**CI**
- A manual `workflow_dispatch` of tests.yml could publish a green `tests` check on a lot head and bypass the freeze gate. It is now refused outside `main`, `release/**`, `integration/**` and `validation/**` and on the head of an open PR, and dispatch runs publish `tests (dispatch)` (#1635).
- CI parts gate (#1666): only a commit status proves a part, never a run or check of the same name. The proof is cached per (base, frozen head). The selector runs in a `bwrap` sandbox (network cut, host hidden), with no fallback: a host without `bwrap` refuses the proof. Its whole process group is killed on timeout. Its plan file is read without following links or blocking on a FIFO, up to 1 MiB.
- Reruns: a run restarted with `gh run rerun` (same run id, new attempt) is reopened and followed to its verdict, and failures are tied to their attempt (#901, migration 0429). A short rerun that finished between two passes is reopened by the catch-up (#1573).
- A batch CI run that concluded before the batch declared its branch gets its verdict when the branch appears, so the end of a batch CI wakes the composer (#2021).
- CI-NEXLINK-WAKE: the catch-up keeps the verdict of each head on a base branch, a repository's base is declared with `github.projects.<project>.base` (`develop` for Nexlink, `main` stays a base), and run lists read 100 rows (#1483). The inherited red is judged on the latest result of the newest base head (#1683).
- Aggregate jobs no longer re-queue for hours on a cancelled run. The required `tests` check stays `always()`, so a cancelled run still concludes it red (#876).
- The `tests (flux)` check carries its run and attempt. The sweep reads them first, is bounded, and never changes the required verdict (#1393).
- GitHub read cache: a concurrent increment is no longer lost while counters are written (#1927), and counters are flushed at the end of each watcher pass (#1813).
- CI runner lending (#1256): six hardenings from its second review. For example, root copies the guest-owned cache with `O_NOFOLLOW` and a bounded read (#1416).
- The `carte` measurement workflow runs in 6 psycopg and 4 psql parts to fit its 40-minute ceiling (#2061). The release-only fs-class job reuses the psycopg venv (#1958). The dead `storage.guard_runs()` is removed (#1328).
- Test plan: an exit aliased by assignment, `_exit()` after `from os import *`, a renamed sys/os module or `getattr(sys, 'exit')` now cut the import proof (#1860, #1878).
- Test hygiene:
  - each `scripts/test.sh` run gets its own disposable database, so LISTEN/NOTIFY tests no longer receive each other's notifications (#1992);
  - `test_turn_grace` no longer fails under load (#1917), and `test_l160e` no longer depends on the global git config (#1943);
  - L39 witness: when the host cannot check that a session is closed (open files of a user's gpg-agent unreadable), `adopt` refuses with or without `--force` (#1965).
