B1 — Le workflow image-approve.yml traite toute erreur de docker manifest inspect comme une absence, puis pousse le tag. Une erreur réseau, d'authentification ou serveur peut donc conduire à écraser un tag existant, contrairement au contrat d'immuabilité. La concurrence par github.ref autorise aussi deux refs à publier le même tag simultanément. Refuser toute erreur autre qu'une absence explicitement établie et sérialiser les publications partageant les tags. Les témoins doivent distinguer un manifeste absent d'un registre injoignable ou refusant l'accès.

B2 — Si le tag SHA existe avec le digest D1, le workflow le conserve, mais construit quand même une image locale D2. La base et les dépendances mobiles rendent ce cas possible et la documentation le reconnaît. Si le tag de version manque, docker push version_ref publie D2, puis la comparaison avec D1 échoue seulement après la publication du tag censé être immuable. Promouvoir vers la version le manifeste distant D1 retenu pour le SHA, et vérifier avant publication la source de cette promotion. Témoin attendu : SHA distant D1, build local D2 et version absente produisent une version D1, sans publication de D2.

Les restrictions de dépôt, runner auto-hébergé et timeout sont présents. Le conteneur non privilégié et l'épinglage par digest côté consommation ne ferment pas ces deux défauts du producteur.
