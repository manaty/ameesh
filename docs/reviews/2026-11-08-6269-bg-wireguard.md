# #6269 — bureau-goal pair WireGuard limité à la base centrale : dossier préparé (aucun geste)

Auteur : bureau (BG, famille claude), 08/11 04:2xZ. Contexte : #6002 (adaptateur VM sur BG, détenteur de la clé cloud), tranche 1 aujourd'hui sur tunnel SSH BG→AG2 (`ameesh-vmtunnel`).

## État relevé (lecture seule)
- Concentrateur : `manaty-mesh-1`, endpoint `78.232.53.17:51820`, clé publique `GUovIgGkqLAj2d2stwWet4weM4ySzKmRZqXd/bXwElU=`, adresse `10.77.0.1`. **Aucun accès root depuis les VM** → geste côté concentrateur = owner.
- Pairs connus : AG1 `10.77.0.3`, AG2 `10.77.0.4`, AG3 `10.77.0.5` ; chacun `AllowedIPs = 10.77.0.1/32`, `PersistentKeepalive = 25`, clé privée dans `/etc/wireguard/ameesh.key` (PostUp `wg set`), `wg-quick@ameesh` enabled.
- BG : noyau 6.8 avec module `wireguard.ko.zst` ; **wireguard-tools absent** (`wg`, `wg-quick`) ; IP publique `78.232.62.207`.

## Proposition
- Adresse BG : **`10.77.0.6/32`** (à confirmer libre côté concentrateur — `.2` probablement le poste).
- BG ne route **que** `10.77.0.1/32` ; le concentrateur n'ouvre à `10.77.0.6` que **tcp/5432** (pas de route vers les autres pairs, pas de SSH).

## Étapes
### A. BG (bureau, root), après deux avis hors claude
```sh
apt-get install -y --no-install-recommends wireguard-tools
umask 077; wg genkey > /etc/wireguard/ameesh.key; wg pubkey < /etc/wireguard/ameesh.key > /etc/wireguard/ameesh.pub   # privée jamais affichée
cat > /etc/wireguard/ameesh.conf <<'C'
[Interface]
Address = 10.77.0.6/32
PostUp = wg set %i private-key /etc/wireguard/ameesh.key

[Peer]
PublicKey = GUovIgGkqLAj2d2stwWet4weM4ySzKmRZqXd/bXwElU=
Endpoint = 78.232.53.17:51820
AllowedIPs = 10.77.0.1/32
PersistentKeepalive = 25
C
chmod 600 /etc/wireguard/ameesh.conf
```
L'interface n'est **pas** montée avant l'étape B. La clé publique (`ameesh.pub`) est transmise à l'owner (publique, sans risque).

### B. Concentrateur (owner, root sur manaty-mesh-1)
1. `wg set <iface> peer <pub BG> allowed-ips 10.77.0.6/32` + même bloc `[Peer]` dans la conf persistante.
2. Pare-feu : n'accepter de `10.77.0.6` que `tcp dport 5432` vers `10.77.0.1` ; rejeter le reste depuis `10.77.0.6` (aucun forward vers `10.77.0.0/24`).
3. `pg_hba.conf` : `hostssl ameesh ameesh 10.77.0.6/32 scram-sha-256` (comme les autres pairs), puis `SELECT pg_reload_conf()`.

### C. BG (bureau), bascule
1. `systemctl enable --now wg-quick@ameesh` ; `wg show` (handshake < 2 min).
2. Tests : `psql "host=10.77.0.1 port=5432 dbname=ameesh user=ameesh sslmode=require passfile=…" -c 'select 1'` = 1, `ssl=t` ; `nc -z 10.77.0.1 22` **refusé** ; ping/route vers `10.77.0.3-5` **absents**.
3. `/etc/ameesh-vm-adapter/ameesh.json` : DSN → `host=10.77.0.1 port=5432 … sslmode=require` ; `pgpass` (agent 0600) : ligne `10.77.0.1:5432:ameesh:ameesh:…` (copie de l'existante, sans affichage).
4. Retrait du tunnel : `systemctl --user disable --now ameesh-vm-adapter-tunnel` ; sur AG2 : rm drop-in `50-ameesh-vmtunnel.conf`, `systemctl reload ssh`, `userdel -r ameesh-vmtunnel` (même procédure de contrôle que la pose : `sshd -t`, `sshd -T` root/ameesh inchangés, session tenue).

## Retour arrière
BG : `systemctl disable --now wg-quick@ameesh`, DSN remis sur le tunnel (le tunnel n'est retiré qu'après C.2 vert). Concentrateur : `wg set <iface> peer <pub BG> remove`, règle pare-feu et ligne pg_hba retirées.
