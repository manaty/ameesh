Après 157 secondes, le check affiche pourtant une désobéissance à la porte initialement fermée. Une interruption transitoire du garde peut produire ce cas sans attendre les 600 secondes de calme d’un reclaim normal.

Ne pas supprimer le refus d’un child qui persiste lorsque la porte reste fermée. Le cas unité active sans child est maintenant correctement accepté.

## C3 nouveau — P2 : le témoin de dépassement peut passer sur une erreur de variable

`deploy/guest/ci-runners.sh:378` choisit son branchement avec `${CI_RUNNERS_TEST_STOP_DELAY:-0}`, mais imprime ensuite `$CI_RUNNERS_TEST_STOP_DELAY` sans défaut dans la branche numérique. Quand la variable est absente, `set -u` provoque `unbound variable`. Le nouveau `test_check_refuses_a_runner_alive_after_the_stop_delay` fournit ACTIVE et CHILD, mais ne définit pas STOP_DELAY.

Preuve locale limitée aux fonctions extraites du fichier exact, environnement privé sans cette variable, `HOSTDIR=fixture`, child simulé toujours présent, aucun appel systemd/pgrep/installeur :

- `runner_stop_delay_s` seule retourne 1 et imprime `CI_RUNNERS_TEST_STOP_DELAY: unbound variable` sur stderr.
- `if wait_runner_stops 1` continue malgré cette erreur (contexte conditionnel Bash), affiche `waiting up to s`, puis refuse avec un délai vide évalué comme zéro. Le check peut donc imprimer le message attendu par le témoin négatif et laisser celui-ci vert pour la mauvaise raison.

Les 38 verts annoncés ne ferment pas ce point. Utiliser aussi le défaut lors de l’impression (ou une variable locale déjà normalisée), définir explicitement STOP_DELAY dans le témoin de dépassement, et vérifier séparément le défaut absent ainsi que l’absence d’erreur stderr. Ajouter le cas child arrêté dans le délai pour que le refus ne soit pas le seul chemin couvert.
