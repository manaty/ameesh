# Modules « pilote » : ceux que la CI d'une PR de lot passe AUSSI avec le pilote
# psql (L116). Le reste de la suite ne dépend pas du pilote : il tourne avec
# psycopg sur la PR de lot, et la suite psql complète tourne sur main,
# release/*, integration/*, à la main (workflow_dispatch) et sur une PR de
# release (source ou cible release/* ou integration/*, sans cette liste). Un
# module ajouté ici doit exister
# (scripts/test-parts.py refuse un nom inconnu).
#
# L1211 (canon §3) : sur une branche de lot, le pilote psql ne voit que les
# modules de cette liste retenus par le plan (impactés ou contrat), plus la
# liste « always » déclenchée (#749).
#
# Règle : on liste les tests de la couche base (db.py), des migrations et du
# stockage (ameesh.storage), et ceux qui exercent un comportement propre à un
# pilote (connexion persistante, notifications, nombre d'allers-retours).
#
# Liste additive (L160a) : un module par ligne, sa raison en commentaire sur la
# même ligne, ordre alphabétique, sans doublon ; la lecture range et
# dédoublonne ce qu'une fusion `union` produit (un nom inconnu reste refusé).
# Deux lots qui ajoutent chacun un module touchent ainsi deux endroits
# différents du fichier, sans conflit.
